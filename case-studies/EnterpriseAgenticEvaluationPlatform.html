The problem

A grounding failure that deterministic checks can't see

Most eval demos invent a failure case to solve. This one didn't have to — during manual testing of the target system, a sub‑agent's answer named specific tools that were never in its own retrieved evidence.

It passed every check that only looks at structure: valid JSON, correct schema, a tool call that returned 200. Nothing about the answer's shape was wrong. What was wrong is invisible to that class of check entirely — and that gap is the reason this platform evaluates content, not just format.

Seed bug · anchors Phase 03

The tooling‑trend‑watcher sub‑agent's response named Prometheus, Grafana, and Airflow as trending tools — none of which appeared anywhere in the search snippets it had actually retrieved.

found by manual review, not by any automated gate · caught before deterministic checks would ever flag it

The system under evaluation

market-analyst-agent

A real multi‑agent research tool, not a toy Q&A bot — a job‑market‑analyst and a tooling‑trend‑watcher sub‑agent, each pulling from web/job search, GitHub trending and RSS, deduped through a persistent memory layer, publishing a weekly digest to Telegram over GitHub Actions.

It stays frozen exactly as submitted. AgenticEvals holds a pinned copy and reaches it only through its public entrypoint and a trace‑emission seam — the evaluation harness never edits the system it's evaluating.

The architecture

Four layers, one call path

Traceability feeds evaluation; evaluation gates deployment; guardrails police the live call; observability closes the loop back to the first layer. The published framework this build is scoped against:

Fig. 1 — Production AI Quality Platform Architecture 4 layers · 1 data lake
01

Traceability & lineage

Every trace, prompt, tool call and config version captured under one unified ID before anything is scored.

02

Dual evaluation engine

Deterministic checks (schema, latency, golden diffs) and semantic/statistical checks (LLM‑as‑judge, hallucination) as CI/CD gates that can block deploy.

03

Runtime guardrails

Input interception and output policy wrapped around the live call path — quality enforcement doesn't stop at deployment.

04

Observability & feedback

Drift detection and failed traces flow back into the regression suite, closing the loop into layer one.
