01 · Problem

QA has more real problems than any one tool can solve

Flaky tests, requirement ambiguity, coverage gaps, framework migrations, duplicate test cases, bugs that slip through a green build — each of these is a distinct, specific problem, not a feature of one grand platform.

Most "AI for QA" products pick one of these, wrap it in a dashboard, and call it a suite. AgenticQA takes the opposite approach: treat every problem as its own small, finishable build, and only build what doesn't already exist.

02 · Approach

Build-vs-reuse, checked before every agent

Before writing a line of code for a new agent, three questions get answered in order:

Decision order
  1. Does the underlying tool already solve this natively?
  2. Is there a good open-source project or agent to extend?
  3. Only build from scratch when neither of the above holds.
Example — UI self-healing locators: already solved natively by Playwright 1.56+ (>75% success rate on selector failures, per Microsoft's own benchmark). Not rebuilt. Effort went to genuinely unclaimed ground instead — like defect-leakage analysis, below.
03 · Architecture

A shared shell, not a shared pipeline

Every agent runs as its own independently deployable service — one can be demoed, shipped, or thrown away without touching the others. One shell app browses and launches all of them; it does not pass data between them.

Only three agents share a genuine dependency: a searchable corpus of existing test cases. That shared piece is built once, as its own service, and called by the agents that actually need it — everything else in the catalog stays standalone.

05 · Process

The next agent formalizes a real QA workflow: when a customer reports a bug, the question isn't just "why did it happen" — it's "why didn't our tests catch it." The answer is a specific, traceable classification, not a guess.

07 · Principles

What holds the toolkit together

Toolkit, not monolith

Twenty-plus real QA problems, one small finishable build at a time — never one framework trying to solve all of them at once.

Reuse before building

Every agent is checked against what already ships natively or open-source first. Building is earned, not assumed.

Shell, not pipeline

One launcher app for discovery and demos. Agents stay independently deployable; only real data dependencies get wired up.

Process over prompts

Each agent encodes an actual QA practice — defect leakage analysis, requirement ambiguity review — not a generic "AI does X" pitch.
