Test Pilot

A shift-left testing toolkit that turns requirements straight into reviewed, automatable test cases — with a human checkpoint at every step that matters.

RoleArchitect & Lead Engineer
ContextStaff SDET, Chargebee
ApproachShift-left, human-in-the-loop
Outcome~60% shorter QA cycle

The problem

Traditional QA starts once requirements are "done": someone reads them, writes test cases by hand, and writes automation for each one later, usually in a separate pass.

Every handoff between those stages adds delay, and test coverage quietly drifts away from what was actually specified — by the time automation exists, the requirement has often already changed again.

Architecture & flow

How it works

  1. Reads the requirements

    Takes requirement documents as input as soon as they're ready — before a single manual test case gets written.

  2. Generates BDD test cases

    An AI model drafts Given/When/Then test cases directly from the requirement text.

  3. Human validates the cases HITL

    A reviewer checks the generated BDD cases for correctness and completeness before anything downstream happens.

  4. Sorts automation steps

    Once validated, Test Pilot scans each case's steps: steps that already exist in the automation step library are marked reusable, and steps that don't are flagged as new.

  5. Human reviews new steps HITL

    A reviewer approves — or corrects — the newly flagged steps before any code gets generated for them.

  6. Generates automation code

    On approval, Test Pilot generates the automation code for the new steps and adds them back into the reusable step library for next time.

Impact

~60% Reduction in QA cycle time
2 Human checkpoints kept in the loop by design
Compounding Step library grows automatically with every new requirement
